## Resumen

Acta v0.6.1 reúne dos correcciones compatibles sobre v0.6.0: controles claros
para expandir y contraer los grupos del cuestionario, y una vista previa de
operaciones masivas que utiliza las versiones actuales de las preguntas.
Conserva la Dirección C y la configuración de VersityGW de v0.6.0.

## Cambios

- **Expandir y contraer grupos** ([#29](https://github.com/ruzer/Acta/pull/29)).
  En Organizar, ambos controles están juntos y visibles cuando hay grupos.
  Su alcance incluye otras páginas y preguntas fuera de los filtros; se
  conservan filtros, selección y controles individuales. Una búsqueda muestra
  también los seguimientos de grupos plegados y deshabilita «Contraer todos»
  para mantener visibles las coincidencias.
- **Vista previa con datos actuales** ([#30](https://github.com/ruzer/Acta/pull/30)).
  Después de asignar participantes, la actualización del cuestionario podía
  seguir pendiente al abrir la publicación conjunta. La vista previa ahora
  espera un refresco antes de enviar las versiones al backend. Si falla ese
  refresco, no se envía una vista previa con datos desactualizados.
  Se mantienen las dependencias de publicación, la confirmación explícita,
  la atomicidad y el rechazo de cambios concurrentes.

## Instalación y actualización

Para una instalación nueva, utiliza el tag `v0.6.1` una vez publicado y sigue
[Self-hosting](https://github.com/ruzer/Acta/blob/v0.6.1/docs/SELF-HOSTING.md).
La release distribuye código fuente; no publica imágenes Docker ni binarios.

Para actualizar desde v0.6.0:

1. Haz un backup coordinado de PostgreSQL, objetos y configuración siguiendo
   [Backup y restauración](https://github.com/ruzer/Acta/blob/v0.6.1/docs/BACKUP-RESTORE.md).
2. Comprueba el tag `v0.6.1` y su commit publicado; no uses `main` como versión.
3. Conserva `.env`, el nombre del proyecto Compose y los volúmenes. Ejecuta
   `docker compose up --build -d --wait`.
4. Verifica salud, login, los controles de grupos y una vista previa de
   publicación con preguntas de prueba. No publiques preguntas reales solo
   para verificar la actualización.

No hay migraciones nuevas, cambios de API, contratos, permisos, variables
obligatorias ni almacenamiento. Volver al código de v0.6.0 no exige revertir
esquema; conserva el backup y considera los datos creados después de actualizar.
Los forks deben probar la actualización en su propia rama: esta release no
modifica instalaciones downstream automáticamente.

## Compatibilidad y límites

- Se mantienen los límites documentados de v0.6.0; no se amplía el soporte de
  plataformas ni de proveedores S3.
- La documentación de self-hosting acredita Linux ARM64. No se afirma una
  validación integral adicional de Linux AMD64, multi-node o alta disponibilidad.
- El navegador automatizado es Chromium. Las pruebas focalizadas de teclado,
  reflujo y accesibilidad no equivalen a una certificación WCAG.
- Se conserva la advertencia conocida del build sobre el tamaño del bundle
  JavaScript. El soporte es comunitario, de mejor esfuerzo, y el proyecto es
  pre-1.0.
